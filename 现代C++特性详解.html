这份文档怎么用

你当年用 C++/Qt 写 USB Dongle 拨号上网、短信发送的 PC 软件，底子是有的。这么多年没碰，真正需要补的不是“新知识”，而是两件事：

  1. 把当年学过的 C++ 基础概念重新唤醒——尤其是“类型”这件事；
  2. 理解 C++11 之后加进来的一批“语法糖”到底在替你省什么力气。
一句话方法论

C++ 的每一个“高级特性”，本质都是对 C 语言里某种笨拙写法的封装和简化。只要把特性用 C 模拟一遍，它的价值立刻清晰：不增加新能力，只把“类型记账”的活从你手上拿走，交给编译器。

每一节的阅读姿势都一样：

  • 特性功能：这东西是干嘛的，能解决什么问题；
  • 产生背景：为什么 C++ 非要加它；
  • C++ 怎么实现：编译器在背后做了什么，运行时有没有开销；
  • 怎么用：日常代码里你最常看到什么样子；
  • C 模拟实现：用 C 的语法“拼”出等价效果，看差距在哪；
  • 心法口诀：读陌生代码时，心里怎么把它翻译成人话。

核心心法：C++ 只是替你记类型

C 的做法C++ 的做法本质差别
手写类型名编译器推导谁来做类型记账
手写 malloc/free类型系统管释放谁负责资源生命周期
void* + 抄代码模板生成谁来做代码生成
函数指针 + void* ctxLambda是否自动携带状态

记住这句话就够了：C 把类型、内存、状态都丢给程序员记账；C++ 把这些记账活编码进语言，让你专注业务逻辑。

特性功能：auto 自动类型推导

产生背景

早年的 auto 是个没人用的存储类说明符（表示“栈上局部变量”），基本等于废的。后来 C++ 模板和 STL 越来越复杂，出现一个很现实的问题：

C++98 现实困境 
// 手写极其痛苦，改一下容器类型全工程跟着改
std::vector<std::pair<std::string, std::map<int, std::shared_ptr<Foo>>>>::iterator it = m.begin();

类型信息编译器本来就知道，让人再手写一遍纯属浪费。C++11 就把 auto 改成“类型占位符”，让编译器根据初始化表达式推导类型。Lambda 和模板返回类型也根本写不出来，只能靠它。

C++ 大概是怎么实现的

auto 完全在编译期处理，运行期根本不存在“auto”这个概念。你写 auto x = expr;，编译器内部等价于做一次模板推导，然后把 auto 直接替换成具体类型——生成汇编和手写类型一模一样，零运行时开销。

推导规则：它会“丢东西”

这是从 C 视角最容易误解的地方。auto 按值推导时会丢掉顶层 const、解开引用、让数组退化为指针。你要引用，就得自己写 &。

推导规则 
int  i  = 10;
const int ci = i;
int& ri = i;

auto a = i;   // int             —— 纯拷贝
auto b = ci;   // int             顶层 const 被丢掉
auto c = ri;   // int             引用被解开

auto& r1 = i;  // int&            要别名就自己写 &
auto& r2 = ci;  // const int&      保留底层 const

怎么用

简化迭代器 
auto it = v.begin();              // 不再手写长类型
范围 for 三种姿势 
for (auto x : v)       { ... }   // 拷贝
for (auto& x : v)     { x++; }  // 修改原对象
for (const auto& x : v) { ... }  // 只读，不拷贝
Lambda 类型根本写不出来 
auto cb = [](int a, int b) { return a + b; };  // auto 是唯一写法

用 C 模拟“类似 auto”的能力

C：只能靠人脑推导 + typedef 
int x = 10;
double y = 3.14;

/* 模拟“复杂类型” */
typedef struct { int* data; size_t len; size_t cap; } Vector;
typedef int* VecIter;          // 迭代器就是指针
VecIter it = v.data;             // 等价于 auto it = v.begin()
C 模拟 auto&（引用语义） 
int  x = 10;
int* r = &x;   // C++ 的 auto& ≈ C 的 T*，但更安全、不用解引用
*r = 20;        // 改的是 x
C 模拟泛型（丢类型安全） 
/* 宏：无类型检查、易重复求值 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))

/* C11 _Generic：弱类型分发，这就是模板+auto的前身 */
#define MAX(a, b) _Generic((a), \
    int: max_int, double: max_double)(a, b)

心法口诀

看到心里翻译成
auto x = expr;右边什么类型，x 就是什么类型（拷贝）
auto& x = expr;x 是右边对象的别名，能改
const auto& x = expr;只读引用，不拷贝
auto* p = expr;p 是指针
auto&& x = expr;万能引用，模板代码里才常见
C++ 现代写法 → 编译器眼里的等价代码 → C 模拟 
// C++ 现代写法
for (const auto& n : names) std::cout << n << "\n";

// 编译器眼里的等价代码
for (std::vector<std::string>::const_iterator it = names.begin();
     it != names.end(); ++it) {
    const std::string& n = *it;
    ...
}

// C 模拟版
const char* names[] = {"alice", "bob"};
for (size_t i = 0; i < n; i++) {
    const char* name = names[i];
    printf("%s\n", name);
}
一句话总结

区别不在“能力”，在谁来做类型记账：C++ 编译器做，C 程序员做。

特性功能：范围 for 循环

产生背景

C 里遍历数组永远是 for (int i=0; i<n; i++)，遍历容器要手写迭代器起止、自增、判等——三段式样板代码重复到极点。C++11 的范围 for 把这四步压成一句：告诉它“遍历这个东西里的每个元素”，剩下的交给语言。

C++ 怎么实现

范围 for 是语法糖，编译期会被展开成等价的传统 for + 迭代器，零运行时开销。背后依赖两个约定：

  • 能被 std::begin() / std::end() 取到起止；
  • 有自增 ++ 和判不等 !=。

任何自定义类型只要实现了 begin()/end()，就能用范围 for——这也是它和 auto 经常捆绑出现的原因。

语法糖展开 
// 你写的
for (auto& x : container) x++;

// 编译器展开（伪代码）
auto __begin = std::begin(container);
auto __end   = std::end(container);
for (; __begin != __end; ++__begin) {
    auto& x = *__begin;
    x++;
}

怎么用

三种姿势 
std::vector<int> v = {1,2,3};

for (int x : v)          { ... }     // 拷贝每个元素
for (int& x : v)        { x *= 2; }  // 修改原元素
for (const auto& x : v) { ... }     // 只读大对象，不拷贝

C 模拟实现

C 的固定写法 
int arr[] = {1,2,3};
size_t n = sizeof(arr) / sizeof(arr[0]);

for (size_t i = 0; i < n; i++) {
    int x = arr[i];      // 想“引用”只能写 int* px = &arr[i];
    printf("%d\n", x);
}

想让自定义容器也能“for-each”，C 只能靠宏，这是 glib / uthash 等库的常见套路：

C 用宏模拟 for-each 
#define VEC_FOREACH(ptr, vec) \
    for (int* (ptr) = (vec).data; (ptr) != (vec).data + (vec).len; ++(ptr))

VEC_FOREACH(p, v) {
    printf("%d\n", *p);
}

宏能跑，但类型不安全、作用域诡异、出了 bug 极难调试——这正是 C++ 把它升级成语法的理由。

心法口诀

看到心里翻译成
for (T x : c)对 c 里每个元素拷贝一份给 x
for (T& x : c)对 c 里每个元素取别名，能改原值
for (const T& x : c)只读遍历，不拷贝（大对象必用）
一句话总结

范围 for = 把“如何遍历”从你代码里删掉，只留下“遍历什么”。开销为零，可读性翻倍。

特性功能：结构化绑定（C++17）

产生背景

从 pair / tuple / 结构体里取成员，C++11 时代是 p.first、p.second，或写一堆临时变量再逐个赋值。代码又长又难读，尤其遍历 map 时 it->first、it->second 非常反人类。

C++ 怎么实现

编译期把“元组式对象”的成员绑定到一组名字上，本质是语法糖，零开销。支持 pair、tuple、数组、以及你自己定义的 std::tuple_size / std::get 特化类型。

怎么用

三种典型场景 
std::map<std::string, int> m = { {"a",1}, {"b",2} };

// 遍历 map：不再写 it->first / it->second
for (const auto& [key, val] : m) {
    std::cout << key << ":" << val << "\n";
}

// 拆 pair
auto [id, name] = std::make_pair(42, "alice");

// 拆 tuple，并用 & 修改
auto& [x, y, z] = point;  // 修改 x/y/z 就是改 point

C 模拟实现

C 只能逐个拆 
struct KV { char* key; int val; };
struct KV m[] = { {"a",1}, {"b",2} };

for (size_t i = 0; i < 2; i++) {
    char* key = m[i].key;   // 多写两行拆字段
    int   val = m[i].val;
    printf("%s:%d\n", key, val);
}

心法口诀

看到心里翻译成
auto [a, b] = x;把 x 的第 1、2 个成员分别起名叫 a、b
auto& [a, b] = x;起别名，改 a/b 就是改 x 的成员
const auto& [a, b] = x;只读拆解，不拷贝
一句话总结

结构化绑定 = 给“多返回值”起好名字。你当年在 C 里写 int ret = func(&out1, &out2) 的别扭，C++17 一行解决。

特性功能：nullptr

产生背景

C 用 NULL（本质是 0 或 (void*)0）。问题来了：

NULL 的坑 
void f(int);
void f(char*);

f(NULL);   // 调用 f(int)！因为 NULL 是 0

NULL 类型是整型，遇到重载函数会“选错人”。这是 C 的设计遗留。

C++ 怎么实现

C++11 引入 nullptr，它是一个独立类型 std::nullptr_t 的常量，能隐式转换成任意指针类型，但不能转换成整型。这样重载决议就不会误选整型版本。

怎么用

永远用 nullptr 
int*   p = nullptr;
char*  s = nullptr;
void*  v = nullptr;

if (p == nullptr) ...
if (!p) ...              // 等价写法

C 模拟实现

C 的无奈 
#define NULL ((void*)0)   // 常见定义，但 C++ 里 (void*) 不能隐转成 int*

int*  p = NULL;
char* s = 0;           // 只能靠纪律：指针一律用 NULL
一个 Qt 时代的真实坑

当年 Qt 信号槽、connect 重载繁多，传 NULL 触发“重载不明确”的编译错误很常见。现在统一写 nullptr，编译器和代码都更干净。

心法口诀

看到心里翻译成
nullptr“这个指针当前不指向任何对象”
if (p)if (p != nullptr)
规则

任何新代码里 NULL 和 0 都别再用，一律 nullptr。

特性功能：using 类型别名（C++11）

产生背景

typedef 的写法对人脑不友好，尤其是函数指针和模板别名——后者 typedef 根本做不到。

C++ 怎么实现

纯编译期别名，零开销。using 还支持模板参数化，这是它相对 typedef 的杀手级优势。

对比 
// typedef 写法
typedef void (*Callback)(int);                    // 难读
typedef std::map<std::string, int> StrIntMap;     // 普通别名可以
// typedef std::vector<T> Vec;                   // ❌ 模板别名做不到

// using 写法（语义相同，可读性更好）
using Callback  = void(*)(int);
using StrIntMap = std::map<std::string, int>;
template<typename T>
using Vec = std::vector<T>;                     // ✅ 模板别名

怎么用

模板别名是核心场景 
template<typename K, typename V>
using StringDict = std::map<K, std::vector<V>>;

StringDict<std::string, int> scores;   // = map<string, vector<int>>

C 模拟实现

C 只有 typedef + 宏 
typedef void (*Callback)(int);

#define VEC(T) T*

VEC(int)   arr = NULL;   // 用宏模拟模板别名，无类型检查
规则

现代 C++ 代码里 using 已经基本取代 typedef。看到 using X = ... 就当它是“给类型起绰号”。

特性功能：强类型枚举 enum class

产生背景

C 的裸枚举会污染命名空间，还能隐式转换成整型——这两点都是 bug 温床：

C 枚举的问题 
enum Color { RED, GREEN, BLUE };
enum Fruit { APPLE, BANANA, RED };   // ❌ 编译错误：RED 重定义

void draw(int color);
draw(RED);                            // 能编过，但语义丢失

C++ 怎么实现

enum class 把枚举值放进自己的作用域，且禁止隐式转换到整型，只能显式 static_cast。零开销（底层仍是整数）。

对比 
enum class Color { Red, Green, Blue };
enum class Fruit { Apple, Banana, Red };   // ✅ 不冲突

Color c = Color::Red;       // 必须加作用域
int   i = static_cast<int>(c);   // 必须显式转换

draw(Color::Red);          // 类型不匹配，编译报错

怎么用

还能指定底层类型省内存 
enum class Status : uint8_t { Ok, Err, Busy };   // 只占 1 字节

switch (s) {
    case Status::Ok:   break;
    case Status::Err:  break;
}

C 模拟实现

C 的三种土办法 
/* 1. 前缀命名，防冲突靠人 */
enum Color { COLOR_RED, COLOR_GREEN };

/* 2. 包一层结构体，模拟作用域（但不常用） */
struct Color { enum { Red, Green } val; };

/* 3. 指定大小 */
typedef uint8_t Status;
#define STATUS_OK  0
#define STATUS_ERR 1
心法

enum class = “带身份证的枚举”：不污染命名空间、不偷偷变成 int。任何新代码都该用它，别再用裸 enum。

特性功能：RAII 资源获取即初始化

产生背景

C 里打开文件、加锁、分配内存，都要成对的 open/close、lock/unlock、malloc/free。问题是：中间一旦 return、走到异常分支、或有人忘了，资源就泄漏。你当年写 Qt/USB 程序，串口/设备句柄泄漏是家常便饭。

C++ 怎么实现

RAII 的核心约定只有一条：资源的生命周期 = 对象的生命周期。资源在构造函数里获取，在析构函数里释放。而 C++ 保证：任何对象离开作用域，析构一定被调用——哪怕是因为异常、return、break 离开的。

加锁的 RAII 包装 
struct LockGuard {
    pthread_mutex_t& m;
    LockGuard(pthread_mutex_t& m_) : m(m_) { pthread_mutex_lock(&m); }
    ~LockGuard() { pthread_mutex_unlock(&m); }   // 离开作用域必调用
};

void f() {
    LockGuard g(mu);        // 加锁
    if (error) return;   // 不会死锁，析构自动 unlock
    // ...
}                          // 正常结束也 unlock

这就是 std::lock_guard、std::unique_ptr、std::fstream 全部的共同祖先。

怎么用

现代代码里你已经天天在用 
{
    std::lock_guard<std::mutex> lock(mu);   // 锁住
    shared_data++;
}   // 自动解锁，任何路径都不漏

std::ifstream f("data.txt");   // 析构自动 close
std::vector<int> v;              // 析构自动 free 内存

C 模拟实现

C 的三条出路，都不完美 
/* 1. goto 清理（Linux 内核风格） */
int f() {
    pthread_mutex_lock(&mu);
    if (init() < 0) goto fail;
    if (open() < 0) goto fail2;
    pthread_mutex_unlock(&mu);
    return 0;
fail2: close();
fail:  pthread_mutex_unlock(&mu);
    return -1;
}

/* 2. 代码块 + 宏（GCC 扩展） */
#define SCOPE_EXIT(x) \
    __attribute__((cleanup(x)))

/* 3. 手动纪律：每个路径都 unlock/free —— 不可靠 */

C 没有“作用域结束自动调用函数”的语言机制，只能靠编码规范 + 代码审查来保证不漏。这是 C++ 相对 C 最本质的差距之一。

心法口诀

看到心里翻译成
某个对象被创建它拿了某个资源，记住：它死的时候会还
lock_guard / unique_ptr / ifstream都是 RAII，作用域结束自动清理
大括号 { ... }人为制造作用域，提前触发析构
一句话总结

RAII = 把“记得释放”从程序员的责任，变成编译器的责任。理解了它，智能指针、锁、文件流全是同一件事。

特性功能：智能指针 shared_ptr / unique_ptr

产生背景

C 里 malloc/free 的所有权全靠注释说明：“这个函数 free 还是调用者 free？”忘了就泄漏，多 free 一次就崩溃。在 Qt 这种对象树里，父子所有权靠 QObject 手动维护，一不小心就双重释放。

C++ 怎么实现

两个智能指针对应两种所有权语义，都是栈上的小对象 + RAII，析构时自动 delete：

  • unique_ptr：独占所有权。禁止拷贝，只许移动。内部就是一个裸指针，开销 ≈ 0。
  • shared_ptr：共享所有权。内部有引用计数（控制块），最后一个引用离开才释放。有极小开销（原子操作 + 控制块内存）。
两个指针的开销差异 
std::unique_ptr<Foo> a = std::make_unique<Foo>();  // sizeof == 一个指针
std::shared_ptr<Foo> b = std::make_shared<Foo>();   // 指针 + 引用计数块

a.release();     // 放弃所有权（不释放）
b.use_count();   // 当前有几个持有者

怎么用

三种典型所有权 
// 1. 独占：工厂函数返回值、容器里装对象
std::unique_ptr<Foo> create_foo() {
    return std::make_unique<Foo>();
}
std::vector<std::unique_ptr<Shape>> shapes;   // 多态对象容器

// 2. 共享：缓存、回调上下文、跨线程
std::shared_ptr<Context> ctx = std::make_shared<Context>();
std::weak_ptr<Context>   w   = ctx;           // 旁观者，不增加计数，防循环引用

// 3. 非拥有：只观察，用裸指针或引用
void render(const Foo& f);

C 模拟实现

C 里实现引用计数 
struct RefCounted {
    void*  obj;
    size_t  refs;
};

void* rc_retain(struct RefCounted* p) {
    __atomic_add_fetch(&p->refs, 1, __ATOMIC_SEQ_CST);
    return p->obj;
}
void rc_release(struct RefCounted* p) {
    if (__atomic_sub_fetch(&p->refs, 1, __ATOMIC_SEQ_CST) == 0)
        free(p->obj);      // 最后一个走的人释放
}

这是 Objective-C retain/release、GObject g_object_ref/unref 的同一套机制。C++ 只是把它自动化并绑定到作用域。

心法口诀

看到心里翻译成
unique_ptr<T>“我是唯一主人，我死对象就死”
shared_ptr<T>“大家一起用，最后一个走的关灯”
weak_ptr<T>“我看一眼，不占股份，防循环引用”
T* / const T&“我不拥有它，只是借用”
关键：所有权三种状态
  • 拥有且独占 → unique_ptr
  • 拥有且共享 → shared_ptr
  • 不拥有（借用） → 裸指针 / 引用

读到任何指针，先判断“谁拥有它”——这就是现代 C++ 的内存哲学。

特性功能：引用（不是新东西，但你当年用 Qt 时可能没细想）

产生背景

C 的函数参数只有“传值”和“传指针”。传值大结构体要拷贝，传指针要写 &、要解引用 *、还要判空。引用就是“必须绑定对象、语法像值、本质是别名”的语法糖。

C++ 怎么实现

引用在底层就是一个指针，零开销。但它和指针有三点不同（这是它存在的理由）：

  1. 必须初始化，不能为 null；
  2. 不能重新绑定（一生只认一个对象）；
  3. 不用解引用，用起来像普通变量。
对比 
// 引用：不能为 null，不用解引用
void inc(int& x) { x++; }
int a = 1;
inc(a);                     // 调用干净，不用 &a

// 指针：可为 null，要解引用
void inc(int* x) { (*x)++; }
inc(&a);

怎么用

三种高频场景 
void modify(Foo& f);                // 输出参数，语义清晰
void read(const Foo& f);            // 只读大对象，不拷贝、不修改
Foo& find(int id);                  // 返回引用，可链式赋值

C 模拟实现

C 用指针模拟 
void modify(int* x) { (*x)++; }   // 多一层语法噪音

const BigObj* read(const BigObj* p);
心法

引用 = “语法像值、本质是别名、绝不为空”。C++ 代码里看到 T&，就当它“就是这个对象本人”；看到 T*，就当它“可能是空的、可重新指向”。

特性功能：移动语义与右值引用（C++11）

产生背景

vector、string 这类“持有资源的对象”，拷贝代价很高（要分配新内存 + 逐字节复制）。但很多时候源对象马上就要被扔掉了——比如函数返回一个大 vector、或把一个临时对象塞进容器。C++98 只能老老实实深拷贝，白白浪费。

C++ 怎么实现

C++11 引入右值引用 T&&，让函数能区分“我还能用这个对象”和“我马上扔掉它”。移动构造/赋值的做法是：把源对象的内部资源（指针）直接偷过来，把源对象置为空壳。

移动 = 偷指针 
class Buffer {
    char* data;
    size_t size;
public:
    // 拷贝：老老实实复制
    Buffer(const Buffer& o) : size(o.size), data(new char[o.size]) {
        std::memcpy(data, o.data, size);
    }
    // 移动：直接偷
    Buffer(Buffer&& o) noexcept
        : data(o.data), size(o.size) {
        o.data = nullptr;   // 置空壳，防止 o 析构时释放
        o.size = 0;
    }
};

编译器在“源对象是临时对象/即将销毁”时自动选择移动，无需你手写 std::move。显式 std::move(x) 的意思是：“我承诺不再用 x，请把它当右值处理”。

怎么用

日常能感知到的效果 
std::vector<int> make_vec() {
    std::vector<int> v(1000000);
    return v;          // NRVO/移动，不拷贝百万元素
}
std::vector<int> a = make_vec();

std::vector<int> b = std::move(a);   // O(1) 搬运，a 变空
assert(a.empty());

C 模拟实现

C 里要达到同等效果，只能手写“窃取内部指针”的 swap 逻辑——这正是 glib、内核、Redis 等 C 项目里常见的手法：

C 的手写 move 
struct Buffer { char* data; size_t size; };

void buffer_move(struct Buffer* dst, struct Buffer* src) {
    dst->data = src->data;   // 偷指针
    dst->size = src->size;
    src->data = NULL;        // 置空壳
    src->size = 0;
}

struct Buffer a = {malloc(1024), 1024};
struct Buffer b = {0};
buffer_move(&b, &a);        // 等价于 C++ 的 b = std::move(a)

心法口诀

看到心里翻译成
T&&“右值引用，我承诺调用方这个对象可以拆掉”
std::move(x)“我不再用 x 了，请把 x 当右值处理”
函数返回局部对象编译器自动移动/NRVO，别担心拷贝
读代码的实用结论

日常读代码时你基本不用手写移动构造，只要看懂 std::move 是“这里发生了资源搬运”就够。T&& 在函数参数里还承担万能引用/完美转发的角色，那是模板代码的事，遇到再查。

特性功能：函数模板

产生背景

同一份逻辑要为 int、float、long 各写一份，只有类型不同——C 里只能抄代码或用宏。qsort 选择了用 void* + 函数指针，代价是完全丢失类型信息。

C++ 怎么实现

模板 = 编译期的类型安全的代码生成器。编译器在编译期根据实参类型，为每种用到的类型生成一份独立函数。类型安全、内联友好、零运行时开销（代价是编译慢、二进制略大、报错信息难懂）。

模板 vs 宏 
// C++ 模板：类型安全
template<typename T>
T max(T a, T b) { return a > b ? a : b; }

int   x = max(1, 2);       // 编译器生成 int   max(int,int)
float y = max(1.0f, 2.0f);  // 生成 float max(float,float)

// C 宏：无类型检查、易重复求值
#define MAX(a, b) ((a) > (b) ? (a) : (b))
MAX(++i, j);   // i 可能被加两次！

怎么用

现代写法和 auto 参数 
template<typename T>
void swap(T& a, T& b) {
    T tmp = std::move(a);
    a = std::move(b);
    b = std::move(tmp);
}

// C++20：缩写形式（看起来像动态类型，其实是模板）
auto add(auto a, auto b) { return a + b; }

C 模拟实现

C 的三种替代，各有权衡 
/* 1. 宏：最简单，最不安全 */
#define MAX(a, b) ((a) > (b) ? (a) : (b))

/* 2. _Generic（C11）：有类型分发，但每个类型要手写一份实现 */
int   max_i(int a, int b)   { return a > b ? a : b; }
double max_d(double a, double b) { return a > b ? a : b; }
#define MAX(a, b) _Generic((a), int: max_i, double: max_d)(a, b)

/* 3. void* + 回调：qsort 风格，完全丢失类型安全 */
void qsort(void* base, size_t n, size_t sz,
             int (*cmp)(const void*, const void*));
一句话总结

模板 = 编译期的类型安全的代码生成器。C 想达到同等效果，要么抄代码，要么用 void* 牺牲类型安全，要么用 _Generic 抄得稍微优雅一点。

特性功能：类模板与容器（vector / map）

产生背景

通用容器是模板最成功的应用。vector<int>、vector<Foo>、map<string, int> 逻辑完全相同，只是元素类型不同。手写就是抄 N 份，void* 实现则牺牲类型安全。

C++ 怎么实现

和函数模板一样，编译器为每种“模板参数组合”生成一份独立类。vector<int> 和 vector<Foo> 是两个完全不同的类型，彼此不兼容。

怎么用

这四类容器你读现代代码必遇到 
std::vector<int>         v;     // 动态数组，连续内存，尾插 O(1)
std::map<int, int>       m;     // 红黑树，按 key 有序，O(log n)
std::unordered_map<K,V> um;    // 哈希表，平均 O(1)
std::deque<T>          dq;    // 双端队列，头尾都能插

C 模拟实现

C 里没有一个通用方案能同时做到“类型安全 + 通用”。通常是给每种类型手写一份容器，或用 void* 加 sizeof 偏移自己维护。

C 手写一个能用的 vector 
typedef struct {
    void*  data;     // 裸内存块
    size_t  elem_size;// 元素大小，必须自己记
    size_t  len;
    size_t  cap;
} Vec;

void vec_init(Vec* v, size_t elem_size) {
    v->data = NULL; v->elem_size = elem_size;
    v->len = v->cap = 0;
}
void* vec_at(Vec* v, size_t i) {
    return (char*)v->data + i * v->elem_size;  // 自己算偏移
}
void vec_push(Vec* v, const void* elem) {
    if (v->len == v->cap) {
        v->cap = v->cap ? v->cap * 2 : 4;
        v->data = realloc(v->data, v->cap * v->elem_size);
    }
    memcpy((char*)v->data + v->len * v->elem_size, elem, v->elem_size);
    v->len++;
}
void vec_free(Vec* v) { free(v->data); }
C 实现的三个硬伤
  • vec_at(v, i) 返回 void*，编译器不帮你检查类型，传错类型静默通过；
  • 扩容逻辑、elem_size 记账、free 全靠自己，忘了就崩；
  • 没法给元素自动调用构造/析构，存 string 这类带资源的类型会出事。

这就是你当年用 Qt 时 QList、QVector 的价值所在——现代 C++ 直接把这套做进了标准库。

心法口诀

看到心里翻译成
vector<T>“会自己扩容的数组”
map<K,V>“按键排序的字典，插入查找 O(log n)”
unordered_map<K,V>“哈希表字典，平均 O(1)”
v.push_back(x)“尾插，可能触发扩容”

特性功能：变参模板与折叠表达式（C++11/17）

产生背景

C 有 va_list，但它在运行时只拿到一堆字节，完全丢失类型信息——参数个数、类型全靠赌命，printf 的 %d 对不上 int 就未定义行为。

C++ 怎么实现

变参模板在编译期就把参数包展开，每个实参的类型都精确可知，展开成真正的类型安全调用。C++17 的折叠表达式更进一步，把“对包里每个元素做同一件事”压缩成一行。

类型安全的 printf 与折叠表达式 
// C++11：递归展开（经典写法）
void print() {}
template<typename T, typename... Args>
void print(T first, Args... rest) {
    std::cout << first << " ";
    print(rest...);
}

// C++17：折叠表达式，一行搞定
template<typename... Args>
void print_all(Args... args) {
    (std::cout << ... << args) << "\n";   // 折叠：对每个 args 都做 <<
}

C 模拟实现

C 只能靠 va_list + 格式串赌命 
#include <stdarg.h>
void print(const char* fmt, ...) {
    va_list ap;
    va_start(ap, fmt);
    /* 按 fmt 逐字符解析，类型完全靠程序员保证 */
    va_end(ap);
}
心法

看到 typename... Args 或 Args... args，心里就当它是“参数个数不定的、每个都有明确类型的一组参数”——C 的 va_list 是它的不安全前身。

特性功能：decltype 与 declval

产生背景

你有一个表达式，想知道它是什么类型，但这个类型名字写不出来（比如“某个函数调用的返回类型”）。模板里尤其常见。

C++ 怎么实现

decltype(expr) 让编译器求表达式的类型（不求值，编译期）。std::declval<T>() 能在不构造对象的前提下“假装”出一个 T 类型右值，用来喂给 decltype。

用法 
int x = 10;
decltype(x)     y = 20;   // int
decltype(&x)    p = &x;   // int*

// 典型场景：让返回类型跟着参数类型走
template<typename A, typename B>
auto mul(A a, B b) -> decltype(a * b) {
    return a * b;
}

C 模拟实现

C 里无法表达“表达式的类型”，只能手动写死返回类型，或用 _Generic 做有限的类型分发。这也是 C 没法实现真正泛型的原因之一。

心法

decltype = “问编译器：这个表达式是什么类型？”。日常读代码遇到，当作“编译器帮我推导了一个我写不出的复杂类型”即可。

特性功能：Concepts（C++20）

产生背景

模板报错是出名的“一万行编译错误”——因为约束发生在模板内部，调用方传错类型时，错误要到很深的地方才暴露。Concepts 把约束提前到模板入口。

C++ 怎么实现

编译期谓词：检查某个类型是否满足一组要求（有某个成员函数、支持某个运算符等）。不满足时，在模板声明处给出可读错误，而不是在实例化深处崩溃。

对比 
// C++20：约束清晰、报错可读
template<typename T>
concept Integral = std::is_integral_v<T>;

template<Integral T>
T add(T a, T b) { return a + b; }

// 之前：SFINAE / enable_if，极其难读
template<typename T,
         typename = std::enable_if_t<std::is_integral_v<T>>>
T add(T a, T b);

C 模拟实现

C 没有等价物。想限制宏或 _Generic 的可用类型，只能靠文档说明 + 静态断言。

心法

template<Concept T> = “这个模板只接受满足某条件的类型”。读到它，当作更严格、更好报错的模板即可，不必深究 Concept 定义细节。

特性功能：std::string

产生背景

C 的 char* 是以 \0 结尾的裸数组，字符串操作全靠 strcpy/strcat/sprintf——天天担心缓冲区溢出，拼接还要手动 malloc/realloc。这是 C 最危险的部分。

C++ 怎么实现

std::string 内部管理一块动态内存，自动扩容、自动 \0 结尾、析构自动释放。配合移动语义，传参和返回都很便宜。

C++ 的日常 
std::string s = "hello";
s += " world";                  // 自动扩容
std::string sub = s.substr(0, 5);
if (s == "hello world") ...       // 运算符重载，直接比较内容
const char* cstr = s.c_str();     // 和 C API 交互时再取裸指针

C 模拟实现

C 的手工拼接（危险） 
char buf[256];
strcpy(buf, "hello");
strcat(buf, " world");   // 超 256 字节就缓冲区溢出

/* 动态版本要自己管理内存 */
char* s = malloc(6);
strcpy(s, "hello");
char* t = realloc(s, 12);
strcat(t, " world");
free(t);
心法

std::string = “会自己管内存的字符串”。只有和 C API 交互（如 USB/串口驱动、系统调用）时才取 .c_str() 转回 const char*。

特性功能：算法 + Lambda

产生背景

C 的 qsort/bsearch 要手写比较函数，void* 无类型安全，而且无法携带状态。想“按某个动态阈值过滤”，只能靠全局变量——这在你当年写 Qt 回调时应该深有体会。

C++ 怎么实现

Lambda = 一个匿名函数 + 一个编译器自动生成的结构体（捕获列表就是结构体的成员）。它替代了 C 里“函数指针 + void* context”的丑陋组合。无捕获的 lambda 还能隐式转换成函数指针。

Lambda 的本质展开 
// 你写的 lambda
int threshold = 10;
auto pred = [threshold](int x) { return x > threshold; };

// 编译器等价的展开
struct __Lambda1 {
    int threshold;
    bool operator()(int x) const { return x > threshold; }
} pred = { threshold };

怎么用

标准算法 + Lambda 的组合 
auto it = std::find_if(v.begin(), v.end(),
                    [](int x) { return x > 10; });

int sum = std::accumulate(v.begin(), v.end(), 0);

std::sort(v.begin(), v.end(),
     [](int a, int b) { return a > b; });    // 降序

C 模拟实现

C 的“函数指针 + void* ctx” 
struct PredCtx { int threshold; };

int pred_gt(void* ctx, int x) {
    return x > ((struct PredCtx*)ctx)->threshold;
}

/* 任何想接受谓词的 C API 都得带 void* context 参数 */
void* find_if(int* begin, int* end,
                  int(*pred)(void*, int), void* ctx);

Qt 的信号槽、GLib 的 g_signal_connect 全是这套模式——这正是 Lambda 要解决的问题。

捕获方式口诀

捕获含义
[]不捕获任何外部变量
[x]按值捕获 x（拷贝一份）
[&x]按引用捕获 x（能改外部）
[=]按值捕获所有用到的变量
[&]按引用捕获所有用到的变量（小心悬空引用）
[this]捕获当前对象指针（Qt 槽函数常见）
一句话总结

Lambda = 带状态的函数对象。读代码时把它当成“一个就地定义的小函数”即可，捕获列表就是它携带的变量。

特性功能：虚函数与运行时多态

产生背景

你当年写 Qt，QWidget、QPushButton 这种“基类指针指向派生类对象，调用同名函数走实际类型”的机制，就是虚函数多态。C 没有虚函数，只能手写。

C++ 怎么实现

每个有虚函数的类，编译器会给它加一张虚函数表（vtable）：一个函数指针数组；对象内部藏一个 vptr 指向这张表。调用虚函数 = 通过 vptr 查表跳转到实际函数。这是 C 手写虚函数的真身。

C++ 写法 
struct Shape {
    virtual ~Shape() = default;
    virtual void draw() const = 0;   // 纯虚：子类必须实现
};
struct Circle : Shape {
    void draw() const override { ... }
};

Shape* s = new Circle;
s->draw();      // 运行时查 vtable，调到 Circle::draw

C 模拟实现

C 手写 vtable 
struct Shape;
struct ShapeVtbl {
    void (*draw)(const struct Shape*);
    void (*destroy)(struct Shape*);
};
struct Shape {
    const struct ShapeVtbl* vtbl;   // 虚表指针
};

void shape_draw(const struct Shape* s) { s->vtbl->draw(s); }

/* Circle 实现：填充自己的 vtbl */
struct Circle { struct Shape base; int r; };
void circle_draw(const struct Shape* s) { ... }
const struct ShapeVtbl Circle_vtbl = { circle_draw, circle_destroy };

这正是 GObject、COM、Linux 内核的 struct file_operations、以及 C++ 编译器内部的实现方式。

心法

虚函数 = 编译器替你维护的函数指针表。看到 virtual，就知道“这个调用在运行时才决定走哪个实现”。

特性功能：override 与 final（C++11）

产生背景

C++98 里重写虚函数只要签名“差不多”就行。拼错函数名、参数类型写错、const 漏了——编译器一律不报错，默默给你一个新函数，运行时多态就失效了。这是 C++ 著名的坑。

C++ 怎么实现

纯编译期检查。override 告诉编译器“我意图重写父类虚函数，请帮我验证”；final 表示“禁止子类再重写”。

对比 
struct Base {
    virtual void draw(int x) const;
    virtual void name();
};
struct Deriv : Base {
    void draw(int x) const override;   // ✅ 编译器验证匹配
    void nane()  override;            // ❌ 拼错，编译报错
    void draw(int x) final;              // 子类不能再重写
};
规则

任何重写虚函数的地方都写 override。它不增加任何开销，纯粹是给你和编译器的一份保险单。

特性功能：统一初始化 {}（C++11）

产生背景

C++98 里初始化五花八门：数组用 {}、结构体用 {}、对象用 ()、聚合又要另一种。而且 T() 和 T(1) 在某些场景有诡异歧义。{} 统一了这一切。

C++ 怎么实现

{} 初始化走初始化列表机制，编译期检查“能否用这组值构造对象”。它还有一个附带好处：禁止窄化转换（如 double → int 会报错）。

对比 
// C++11 起：统一用 {}
std::vector<int> v = {1, 2, 3};       // 列表初始化容器
int a[3] = {1, 2, 3};
std::pair<int, int> p = {1, 2};
int  x{42};
double d = 3.14;
int  y{d};     // ❌ 编译错误：窄化转换被禁止

C 模拟实现

C 的指定初始化器（C99） 
int  a[] = {1, 2, 3};
struct Point p = { .x = 1, .y = 2 };   // 指定成员名，可读性更好
心法

现代 C++ 里默认用 {} 初始化，既统一又安全。只有“明确要调用某个构造函数”或某些需要缩窄的特殊场景才用 ()。

特性功能：constexpr 编译期计算

产生背景

C 用宏和枚举表达“编译期常量”，但宏无类型检查、易重复求值、作用域混乱。constexpr 把“能在编译期算出来的东西”变成语言的一等公民。

C++ 怎么实现

编译器在编译期对 constexpr 函数/变量求值，结果直接嵌入二进制，运行期零开销。C++14 起 constexpr 函数可以包含多条语句、局部变量、循环。

对比 
// C++ constexpr：有类型、可调试
constexpr int sq(int x) { return x * x; }
constexpr int val = sq(5);      // 编译期算出 25，嵌入二进制

// C 宏：无类型、重复求值
#define SQ(x) ((x) * (x))
int a[SQ(5)];    // 能用，但 SQ(++i) 会坑你

C 模拟实现

C 的替代方案 
enum { SQ5 = 25 };            // 编译期常量，但语义别扭
static const int sq5 = 25;   // 常量，但不是“编译期函数”

/* C23 起才有 constexpr，老代码无等价物 */
心法

constexpr = “告诉编译器：这个值/函数的结果可以在编译期确定，请直接算好”。读代码看到它，知道“这是个编译期常量/计算”，性能无忧即可。

特性功能：std::optional（C++17）

产生背景

C 的函数想表达“可能没有值”，要么返回哨兵值（-1、NULL），要么用出参 int* out_err，要么返回结构体 {bool ok; T val;}——三种都啰嗦且不统一。更糟的是哨兵值可能和有效值冲突。

C++ 怎么实现

std::optional<T> 内部是一个 bool（是否有值）+ 一块足够放 T 的内存（用 union/aligned_storage 避免不必要的构造）。开销很小，零堆分配。

用法 
std::optional<int> find_id(const std::string& name) {
    if (exists(name)) return 42;
    return std::nullopt;     // 明确表达“没有值”
}

auto id = find_id("alice");
if (id) {
    use(*id);              // 解引用取值
    use(id.value_or(0));     // 没有就给默认值
}

C 模拟实现

C 的三种土办法 
/* 1. 哨兵值（可能冲突） */
int  find_id(const char* name);

/* 2. 出参 */
bool find_id(const char* name, int* out);

/* 3. 返回“带标记的结构体”（最接近 optional） */
typedef struct { bool ok; int val; } OptionalInt;
OptionalInt find_id(const char* name);
心法

optional<T> = “返回值可能存在，也可能不存在”。比哨兵值安全、比出参干净，是现代 C++ 里表达“可空”的首选（而不是返回指针）。

特性功能：std::variant / std::any（C++17）

产生背景

C 的 union 只能存 Plain Old Data，且不知道自己现在存的是哪个类型——得另配一个 tag 枚举，手动记、手动判，忘判就是未定义行为。variant 把这套“tagged union”做成了类型安全的库类型。

C++ 怎么实现

variant<A, B, C> 内部是一块能容纳最大类型的存储 + 一个索引（现在装的是第几个类型），访问时通过 std::get 或 std::visit 编译期保证类型正确。

用法 
std::variant<int, std::string> v = 10;
v = "hello";                        // 现在装 string

if (auto p = std::get_if<int>(&v)) {
    use_int(*p);
} else if (auto s = std::get_if<std::string>(&v)) {
    use_str(*s);
}

C 模拟实现

C 的 tagged union 
enum ValKind { VAL_INT, VAL_STR };
typedef struct {
    enum ValKind tag;      // 手动记“现在是哪个类型”
    union {
        int         i;
        char*       s;
    } u;
} Val;

void val_print(const Val* v) {
    switch (v->tag) {        // 忘了更新 tag 就出事
        case VAL_INT: printf("%d\n", v->u.i); break;
        case VAL_STR: printf("%s\n", v->u.s); break;
    }
}
心法

variant = “带身份证的 union”；any = “能装任何类型，但代价是类型擦除 + 堆分配”。需要表达“多种类型之一”时，优先 variant。
